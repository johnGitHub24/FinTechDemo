FinTechDemo — 分散式系統落地（微服務 × Kafka × Redis）

展示主敘事：Distributed System Demo（不是單機 CRUD）。

三個業務微服務（至少）

服務 埠 職責
order-service 8081 登入 JWT、訂單、審計、發 Kafka；WebConfig CORS
risk-service 8082 名義金額風控（Feign 被叫）
account-service 8084 餘額／持倉帳本、Redis cache、消費 trade-events
job-service 8083 排程輔助（非業務主鏈）
gateway 8080 依路徑路由到 order／account；RateLimitWebFilter

Kafka Event Bus

POST /api/orders
   └─ Producer → topic order-events
        └─ order Consumer → Feign risk → 改訂單 ACCEPTED
             └─ Producer → topic trade-events
                  └─ account Consumer → 入帳 + 清 Redis cache
Topic Producer Consumer 之後做什麼
order-events order order 呼叫 risk-service，執行帳務編排
trade-events order account 更新現金／持倉，evict Redis
  • 預設 fintech.kafka.enabled=false（單元／整合測試與 standalone 不依賴 broker）
  • Demo：docker compose up -d + --spring.profiles.active=demo（order 與 account 都開 demo）

Redis Cache

項目 說明
落點 account-service
Key account:{userId}、positions:{userId}
TTL 600s（fintech.redis.ttl-seconds；種子啟動會預熱 key）
失效 入帳（Kafka／Feign apply-trade）後 evict
本機 Demo 預設 fintech.redis.enabled=true；開啟Demo.cmd 會 docker compose up -d redis（-SkipDocker 才略過）
測試 src/test/resources/application.properties 關 Redis＋exclude autoconfig
連線失敗 QueryService warn 後改打 H2，不擋查詢

Note：只有 account 連 localhost:6379。order／risk／gateway／job 本機預設不連 Redis；開 Redis 不會改那些服務的行為。

NOTE：evict 是什麼？

evict = 刪掉快取 key，不是刪帳本。正式資料在 H2 accountdb；Redis 只加速讀。

  1. 讀：先 Redis → miss 再 H2 → 回填快取（TTL 600s）。
  2. 寫後 evict：入帳成功刪 account:{id}／positions:{id}，下次讀到新數字。
  3. 觸發：Feign apply-trade、TradeEventConsumer 入帳後 → queryService.evict(userId)。

若不 evict 會髒讀。讀碼：AccountQueryService.evict。手冊：handbook §4 · db.html。

雙路徑一致性

模式 行為
Kafka Demo trade-events → account 最終一致（kafka=true 時程式略過 Feign，不必關 feign-sync）
Feign sync（本機預設） fintech.account.feign-sync=true 且 kafka=false → order 同步打 account 內部 API（Gateway Portal 讀 account 才對得上）
Standalone 只起 order：改 feign-sync=false；portal 直打 :8081 讀本機帳本

NOTE（失敗與 rollback／未來擴增）：

  • Feign：AccountSyncService.syncTrade 失敗拋錯 → TradingService.execute 的 @Transactional 回滾 order DB（單庫回滾，不是 Saga 補償）。
  • Kafka：order 先 commit 再 publishAfterCommit；account 消費失敗不會自動 rollback order；目前沒有 Saga／TCC／補償交易。
  • 未來可擴增（Kafka 路徑）：補償交易（沖銷 order／compensate topic）、編排式 Saga、或 TCC；接到 TradeEventConsumer／outbox 即可演進，不必改雙庫邊界。
  • 詳表：handbook §5.7.1 · db.html。

Gateway 路由

  • /api/accounts/**、/api/positions → account:8084
  • 其餘 /api/** → order:8081
  • 限流：RateLimitWebFilter（fintech.gateway.rate-limit.*）；超限 429

前端 Vite：standalone 預設 :8081；分散式設 VITE_API_TARGET=http://localhost:8080。
Order 另有 WebConfig CORS（允許 :5173 直連，不必只靠 proxy）。
