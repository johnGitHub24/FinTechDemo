1. 三條 Demo 路線（先選一條，勿混）

常見搞混：npm run dev 只起前端；OrderServiceApplication 只起本機 JVM；start-k8s-demo.ps1 只起叢集 Pod。三者互不會自動帶起對方。
路線 A — 日常業務 Demo（IntelliJ / 開啟Demo.cmd） 
IntelliJ OrderServiceApplication  →  localhost:8081
npm run dev                       →  :5173，proxy /api → :8081
瀏覽器 /login → 下單成交

不需要 K8s。Order 就緒後可能背景跑 ensure-demo-links 補 Risk、Vite，仍不是 K8s。

路線 B — 純 K8s 部署證明（面試加分） 
.\demo\start-k8s-demo.ps1
.\demo\k8s-walkthrough.ps1
kubectl -n fintech-demo get pods   # 4× Running
kubectl port-forward svc/gateway 18080:8080
curl http://localhost:18080/actuator/health

四服務在 叢集內；本機 :8081 預設沒有服務，除非 port-forward。

路線 C — K8s 後端 + 前端一起 
# 視窗1：K8s 已 Running 後
$env:KUBECONFIG = ".\demo\.tools\kubeconfig-kind-trading-local"
kubectl -n fintech-demo port-forward svc/order-service 8081:8081
# 或 gateway → 18080 且前端 VITE_API_TARGET=http://localhost:18080

# 視窗2
cd frontend; npm run dev

前端預設 proxy 目標 http://localhost:8081（見 frontend/vite.config.js）。

你啟動的起了什麼會順便起 K8s？
npm run devVite :5173否
IntelliJ OrderServiceApplication本機 JVM :8081否
start-k8s-demo.ps1kind 內 4 Pod否（不含前端）

6. Docker Desktop Settings（Enable Kubernetes）

Settings → Kubernetes → Enable = 起 A 棟（docker-desktop，節點 desktop-control-plane）。

  • 與 B 棟 都叫 kind 技術，但是不同 cluster 名稱
  • Settings 不會列出 fintech-demo namespace
  • 只做 FinTechDemo K8s Demo 可關閉 Enable，只留 Docker 引擎 + start-k8s-demo.ps1（省 RAM）
  • 「Waiting for node to be ready」久 → 加 Memory、等 10～15 分鐘、或 Reset cluster

7. IntelliJ 連 B 棟（可選）

  1. Plugins → Kubernetes（不是 Docker 插件）
  2. Settings → Kubernetes → Kubeconfig +：demo\.tools\kubeconfig-kind-trading-local
  3. Services → + Kubernetes → kind-trading-local → namespace fintech-demo

詳細：intellij-k8s.md

12. 前端怎麼打包成 Docker 映像

專案已有 frontend/Dockerfile：Stage1 npm run build → Stage2 nginx 提供 dist，/api 反代 gateway:8080（見 frontend/nginx.conf）。

cd FinTechDemo
docker build -t fintech-demo/frontend:local ./frontend
docker compose --profile full up -d frontend
# 瀏覽器 http://localhost:5173 （映射容器 80）
模式怎麼跑前端/api 打到哪
Local 日常npm run dev 或 開啟Demo.cmdVite proxy → localhost:8081（Order bootRun）
Docker Desktop 映像docker compose --profile full up -d frontendnginx → compose 內 gateway:8080
kind 四 Pod目前沒有 frontend Deployment仍用 Vite；需 port-forward 8081 或 18080
映像裡的 nginx 不會連 IntelliJ OrderServiceApplication。bootRun 與 compose frontend 是兩條路，勿混用同一 :5173。

13. ENABLE_K8S：前端啟動時要不要順便起 K8s

Vue / npm / YAML 都不能啟動 kind。瀏覽器沒有權限建叢集。開關必須寫在 Demo 腳本讀的 properties，不是前端 yaml。

已加旗標：demo/platform-run.properties

# false＝只 local（IntelliJ Order + Vite）
ENABLE_K8S=false
# true＝開啟Demo.cmd 在本機服務之後再跑 start-k8s-demo.ps1
ENABLE_K8S=true
值開啟Demo.cmd 做什麼
false（預設）Order／Risk／Vite 本機 — 不起 kind
true本機照跑，再加上 kind fintech-demo 四 Pod

單次覆蓋（不改檔）：

.\demo\ensure-demo-links.ps1 -EnableK8s
.\demo\ensure-demo-links.ps1 -SkipK8s

true 之後前端仍預設連本機 :8081（路線 A）。要連 Pod：先停 bootRun，再

$env:KUBECONFIG = ".\demo\.tools\kubeconfig-kind-trading-local"
kubectl -n fintech-demo port-forward svc/order-service 8081:8081

或 gateway 18080:8080 + $env:VITE_API_TARGET='http://localhost:18080' 再開 npm run dev。

RAM：本機 JVM + kind 節點會搶記憶體；日常請保持 ENABLE_K8S=false。
