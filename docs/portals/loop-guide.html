部署跑通 — Loop Engineering 通用教學指導

目標不是「程式能編譯」而已，而是功能可部署成功：Compose 健康 +（若要 K8s）Pod Ready + health UP。 本頁是可重複使用的通用解法：遇到同類問題，照關卡與症狀表執行即可。

統一學習入口 學習導引地圖 K8s 故障排除 S0→S6 階段層次 分散式落地 deploy README

心法：為什麼要這樣執行？

  • 開發綠燈 ≠ 部署成功：gradlew check 只證明測試；Compose／K8s 才證明「程序能起來並被探測到」。
  • 先窄後寬：先修引擎（Docker）→ 再修契約（kustomize）→ 再真跑（compose／kind）。跳關會把時間花在假問題上。
  • Loop Engineering：每關失敗就診斷 → 修最小根因 → 重跑同一關 → 綠燈才進下一關。禁止「一次改十處猜」。
  • 證據優先：用 docker info、kubectl get --raw=/readyz、describe、logs、exit code 說話，不要先改業務 Java。
flowchart LR A["症狀"] --> B["定位層級
L0~L4"] B --> C["最小證據
info / logs / describe"] C --> D["修根因"] D --> E["重跑同一關"] E -->|紅燈| C E -->|綠燈| F["下一關"]
禁止：看到 connection refused 就改 Spring 設定；那通常是 Docker／kubeconfig／叢集死掉。

關指令通過標準為什麼先做這關

Compose 跑通（L3）— 為什麼這樣做

為什麼先 Compose？ 同一份 Dockerfile／埠號／healthcheck，失敗成本低；Kafka＋Redis 已編排好。K8s overlay 示意常不含 infra，不適合當「業務可 Demo」唯一路徑。
  1. 確認引擎：docker info（必須看到 Server Version）。
  2. 建並起核心服務： 
    cd D:\ClaudeCode\FinTechDemo
docker compose up -d --build
docker compose ps
  3. 等到全部 (healthy)（含 gateway）。
  4. 煙霧：.\scripts\verify-pipeline.ps1 -Smoke → health UP（order／risk／account）。
通過＝「功能可部署成功」的最低線。日常 Demo 到這裡通常就夠。

Kind 真部署（L4）— 為什麼這樣做

為什麼分四步？ kind 節點看不見本機 Docker 映像庫，必須 kind load；沒 load 會 ErrImageNeverPull。沒活 API 就 apply 會 connection refused。
sequenceDiagram participant D as Docker participant K as kind trading-local participant A as kubectl apply participant P as Pods D->>D: docker info OK D->>K: kind create / recreate K->>K: readyz = ok D->>K: kind load docker-image *:local A->>P: apply overlays/dev P->>P: startupProbe 通過 P->>P: Ready 1/1

為什麼要改 probe／記憶體？（本專案實戰根因）

  • 症狀：Pod Running 但 0/1、重啟多次、terminated Exit Code 137。
  • 證據：Events 有 Liveness probe failed → Killing；log 顯示 Spring Boot 啟動 > 40s。
  • 根因：四個 JVM 同節點搶 CPU／RAM；liveness 太早；limit 512Mi 易被壓死。
  • 解法（通用）：加 startupProbe（啟動期不殺）、提高 memory limit、JAVA_TOOL_OPTIONS=-XX:MaxRAMPercentage=70.0。
記住：liveness 是「救死鎖」，不是「催促啟動」。慢啟動用 startupProbe。

5) kind ≠ Docker Desktop「Enable Kubernetes」

為什麼 Desktop 勾選後看不到 FinTechDemo？ 本專案預設部署在 kind 叢集 trading-local（context：kind-trading-local）。 Docker Desktop Settings → Kubernetes → Enable Kubernetes 是另一套叢集（context 常為 docker-desktop）。 兩邊互不相通；看不到 Pod 是正常的，不是部署失敗。
項目本專案（預設）Docker Desktop K8s
怎麼起叢集 kind.exe create --name trading-local Desktop UI「Enable Kubernetes」
kubectl context kind-trading-local docker-desktop
節點名 trading-local-control-plane 通常 docker-desktop
FinTechDemo Pod kubectl -n fintech-demo get pods 預設沒有（除非改 context 再 apply）
Desktop 開關要不要開 可不開（省資源） 只用 Desktop K8s 時才開 
# 列出所有 context，確認自己連哪一套
kubectl config get-contexts
kubectl config current-context

# 若誤切到 docker-desktop，切回 kind：
kubectl config use-context kind-trading-local
kubectl -n fintech-demo get pods
規則：驗證前先看 kubectl config current-context。 看到 kind-trading-local 才去找 FinTechDemo；不要在 Desktop Kubernetes UI 裡找。

症狀先查解法方向
connection refused 打高位埠 docker info、kubectl get --raw=/readyz 重開 Docker → recreate kind → export kubeconfig
